# 선린밸리 0.2.3 로컬 후보

아직 발행하거나 운영 서버에 적용하지 않은 모드팩 업데이트다. 런처 버전은 1.1.3, 운영 채널은 0.2.2를 유지한다.

사용자가 수정한 2026-10-28 01:29:57 퀘스트북을 기준으로 한다. `1. 시작하기`는 나무 곡괭이 → 코그 5·대장장이 작업대 1·급식 5, `도구 업그레이드?`는 돌 곡괭이 → 코그 5·급식 5·마을 이동권 1이다. 나머지 배치·삭제·보상은 제공된 내보내기 파일을 유지한다. 마을 회관 자동 완료는 제거했고 청크 보호 해금은 내집마련에 연결한다.

마을 이동권 `kubejs:town_warp_ticket`은 주 손 우클릭으로 현재 오버월드 공용 스폰에 이동한다. `/setworldspawn`으로 변경한 위치를 사용하며 개인 침대와 별개다. 안전한 도착과 서버 이동 성공을 확인한 뒤 1개 소모하고, 실패하면 보존한다. 새 아이템 등록이 있으므로 클라이언트와 서버 모두 재시작이 필요하다.

## 로컬 빌드

저장소 루트에서 실행한다. 아래 명령은 업로드·운영 채널 전환·서버 실행을 하지 않는다.

```sh
python3 build-scripts/resolve-pack.py --check
python3 build-scripts/build-resources.py
python3 build-scripts/build-update.py --repo mingyu1715/sunrin-valley --min-launcher-version 1.1.3
python3 build-scripts/build-server-candidate.py
```

클라이언트 발행 후보는 `release/updates/0.2.3`, 서버 적용 후보는 `release/server/0.2.3`에 생성된다. 검증된 기존 Core·Beat Lamp 파일을 로컬에 보유해야 서버 전체 업데이트를 만들 수 있다. Forge와 기존 모드 파일은 바꾸지 않는다.

## 나중에 적용할 때의 진행도 초기화

배포 ZIP에 개인 진행·월드 파일을 넣지 않는다. 기존 월드의 진행도는 모드팩 파일을 바꾸는 것만으로 초기화되지 않으므로, 운영 적용 때 아래 작업을 **명시적으로 한 번** 수행한다.

1. 점검 중 접속을 막고 전체 서버를 백업한다.
2. 기존 업데이트 절차로 0.2.3 파일을 적용한다. 이전 소유 파일 목록에 있던 `sunrin_community_start.js`가 제거되었는지 확인한다.
3. 업데이트 절차가 서버를 재시작했다면 정상 종료한다. **서버가 종료된 상태에서만** 초기화 도구를 실행한다.
4. 실제 서버 경로와 `server.properties`의 `level-name`을 확인한 뒤 아래 명령의 예시 경로를 바꾼다. 기본 명령은 미리보기이며 `--apply`가 있어야 초기화한다.

```sh
python3 server-ops/reset_quest_progress.py --server /srv/sunrin/minecraft --world world
python3 server-ops/reset_quest_progress.py --server /srv/sunrin/minecraft --world world \
  --apply --backup /srv/sunrin/quest-reset-0.2.3
```

5. 서버를 시작해 마을 회관이 자동 완료되지 않는지, 첫 두 퀘스트와 청크 보호 해금이 정상인지 확인한 후 클라이언트 운영 버전을 전환한다.

초기화 범위는 FTB 퀘스트 진행·개인 보상 수령 기록과 해당 퀘스트가 주는 다섯 해금 태그다. 월드·인벤토리·팀·칭호·상자 및 접속 보상 이력은 유지한다. 인벤토리나 기존 개인 성장으로 충족하는 원본 감지 과제는 초기화 후 다시 완료될 수 있다. 수령 기록도 초기화하므로 완료한 퀘스트의 보상은 다시 받을 수 있다.

테스트에서 로그인 전에는 전체 1,131개 퀘스트의 진행·수령 기록이 비어 있음을 확인했다. 접속 즉시 원본 오버월드 감지 퀘스트 1개와 그 환경 설정 보상은 다시 완료될 수 있으며, 마을 회관 30개 자동 완료와는 별개다.

자세한 백업·복원·오류 처리와 정확한 다섯 태그는 [초기화 도구 안내](../../quest-reset-README.md)에 있다. 로그인이나 서버 시작마다 반복하는 초기화 스크립트는 없다.

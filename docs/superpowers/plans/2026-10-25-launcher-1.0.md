# Launcher 1.0 implementation plan

> **For agentic workers:** implement the approved conversation design, with independent module work delegated and shared integration owned by root. Steps use checkbox syntax.

**Goal:** Ship launcher 1.0.0 with deliberate operating-version updates, useful diagnostics, storage estimates, close notices and platform removal.

**Architecture:** Preserve the current Electron/React UI and Prism flow. Add small main-process modules for diagnostics, storage and owned-data removal; expose narrow IPC methods. Keep pack publication and operating versions unchanged.

**Tech Stack:** Electron, React, TypeScript, Vitest, electron-builder NSIS/mac ZIP.

**Spec:** User-approved conversation plan on 2026-10-25 and subsequent storage/uninstaller instructions.

## Global Constraints

- Preserve existing visual design and Windows native caption buttons.
- Installed primary button starts with 게임 실행. First click checks operation; pending update changes button to 업데이트가 있습니다 and returns. Second click applies, then launches after success.
- Never select latest publication instead of operating release. Preserve maintenance and minimum-launcher gates.
- Error UI supports details, copy and a sanitized TXT report; never export accounts, auth cache or raw command lines.
- Show conservative disk estimate before installation and installed bytes in settings.
- Busy close gives 계속 보기 / 창만 닫기 and preserves existing background work.
- Windows uses registered NSIS uninstall; Mac application menu removal. Removal requires confirmation and protects unrelated Minecraft/data paths.
- User deferred Windows hardware/play tests; automated checks and builds remain required. Publish launcher 1.0.0 directly; game operating version stays unchanged.

## Review Focus

- Operating target changing between check and confirmation must require renewed consent.
- ENOSPC/report-save failures cannot recursively open error dialogs or destroy working files.
- Storage scanning/removal must not follow links outside the owned data root.
- Existing game/Prism processes prevent data removal; cancellation makes no mutations.
- Report text, clipboard and saved bytes share one sanitized representation.

# 선린밸리 커스텀 시스템 — 구현 및 확인 목록

2026-10-27 · 후보 모드팩 **0.2.0**, Sunrin Core **0.1.0** · Minecraft 1.20.1 / Forge 47.4.0 / Java 17

## 구현

- **랜덤박스:** 서버 추첨, 원본 SimpleHats 주머니 지급, 클릭 스킵·한 번 더·연속 개봉·확률·수량·실제 결과 표시. 똥 당첨은 금빛 연출 뒤 공개합니다.
- **가구랜덤박스:** 실제 등록을 확인한 **2,026개** 중 하나를 균등하게 즉시 지급합니다. 기본형 제외·인형 초기화 규칙은 데이터로 관리합니다. 인벤토리의 남는 공간을 사용하고 나머지는 발밑에 떨어집니다.
- **이용권:** 기존 건피권·칭호권 ID와 텍스처 유지, 이름 색상 변경권 추가. 칭호와 이름 색을 독립 저장하고 기존 팀을 유지합니다. 급식은 그대로입니다.
- **관리:** `peach_min` UUID만 관리자 목록에 등록합니다. `/sunrin admin`으로 본인의 임시 OP·게임모드를 전환하며, 목록 등록만으로 OP를 부여하지 않습니다.
- **기존 모드:** KubeJS가 확률·접속 보상·건피권을 담당합니다. FTB Chunks는 파티 인원×4청크입니다. StageBox를 Beat Lamp 1.2.2로 교체하고 Music Disc Maker를 유지합니다.
- **업데이트:** 자체 파일만 병합하고 변경 전 백업·실패 복구를 지원합니다. 운영자가 수정한 설정은 보존합니다. 클라이언트와 서버에 같은 Core·스크립트를 적용해야 합니다.

실제 설정은 `config/sunrin/{random-box,furniture-box,geonpi}.json`입니다. 기본값은 최초에만 복사하며 `/sunrinpolicy reload`로 재검증합니다. 잘못된 아이템·확률·시즌 풀이 있으면 상자를 소비하지 않습니다. 시즌 주머니 네 종류 중 하나라도 없으면 차단하며 나머지 시즌 확률을 늘리지 않습니다. [기본 가구 목록](../kubejs-custom/data/sunrin/defaults/furniture-box.json)과 [제외 근거](../kubejs-custom/data/sunrin/furniture-selection.json)를 함께 관리합니다.

## 검증

- 전체 `npm test`, TypeScript 검사, Core 출력이 없는 상태의 `npm run build` 통과.
- 실제 Forge 전용 서버 통합 검사 **38개 통과**. 아이템 등록·2,026개 가구 ID·상자 소모와 지급·가득 찬 인벤토리·부분 스택 습득·중복 방지·손상·누락된 거래 파일 차단·칭호/이용권·관리자 권한 복구 검증.
- macOS Apple Silicon 전체 클라이언트 358개 모드 기동, 실제 GUI 21개 캡처 확인. 논리 크기 320×180·640×360·640×400에서 한글·아이콘·버튼 배치 확인.
- 모든 전원 차단 지점의 원자성은 보장하지 않습니다. 저장 증거가 불확실하면 재지급하지 않고 원본 기록을 보존해 검토하도록 합니다. [복구 명령 안내](../sunrin-core/README.md).

## 나중에 한 번에 확인할 항목

1. **운영 배포:** 후보 0.2.0의 GitHub 발행·운영 채널 전환·AWS 적용 시점. 현재 운영 채널은 0.1.4이며 AWS는 중지 상태를 유지했습니다.
2. **실서버 월드:** 백업 복사본에서 기존 StageBox 설치 블록 유무·제거 영향 확인 후 교체. 기존 월드·플레이어 데이터는 이번 로컬 검증에 사용하지 않았습니다.
3. **실제 플레이 확인:** Microsoft 계정 접속, 두 명 이상에서 채팅·탭·이름표 동기화와 건피권 이동/복귀, Beat Lamp 음악 반응, Windows 실제 실행. 현재 검증은 격리 클라이언트·서버 기준입니다.
4. **NPC·경제·퀘스트:** 기본형 가구 상점의 가격·NPC 위치·직업 조건을 정한 뒤 기존 상점에 연결합니다. 기존 은행·NPC·퀘스트를 유지하며 새 가격이나 퀘스트 해금 정책은 적용하지 않았습니다.

## 적용한 기본값과 조정 시 영향

- 최초 접속에는 두 상자 각각 15개를 UUID당 한 번, 실제 온라인 30분마다 각각 5개 지급합니다. 기존 플레이어도 최초 보상을 받으며 과거 시간은 소급하지 않습니다. 운영 경제에 많거나 적으면 수량을 조정해야 합니다.
- 건피권은 온라인 운영자에게 알림을 보낸 후 소비하며 운영자가 없으면 보존합니다. 토큰은 10분, 복귀 전 다른 호출 이동은 차단합니다. 운영자가 실제 도착하기 전에 이용권이 소비될 수 있습니다.
- 칭호는 NFC 기준 1~10 Unicode 코드포인트, 괄호 제외, 정해진 괄호·색상입니다. 중복 칭호를 허용합니다. 더 엄격한 이름 정책이 필요하면 검증 규칙을 조정해야 합니다.
- 모호한 지급 기록은 후속 지급을 차단합니다. 정상 드롭 청크가 아직 불러와지지 않은 경우에도 재검증이나 운영자 확인이 필요할 수 있습니다.
- 테스트는 격리 복사본에서 진행했습니다. 실제 월드와 여러 사람의 조합에만 나타나는 문제는 운영 전 복사본 테스트로 확인해야 합니다.
